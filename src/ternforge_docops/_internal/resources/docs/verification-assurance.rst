Verification assurance map
==========================

Read each accepted Requirement and Technical requirement as one layered proof path:

``Contract → Implementation → Verification → Runtime assurance``.

The Sphinx-Needs graph remains authoritative for contract, implementation, testcase,
revision, and result relationships. Completeness uses the same current-revision,
passed-evidence health projection as the rest of the portal. Runtime execution path,
boundary interactions, coverage footprint, proof basis, and explicit limits stay in
the retained verification narratives linked from the final layer; this page does not
copy or reinterpret those runtime facts.

.. ternforge-verification-assurance-map::

For the authored hierarchy around these contracts, use :doc:`traceability-reader`.
For the evidence-of-evidence route behind test infrastructure, use
:doc:`evidence-trust`. For aggregate layer counts and release outcomes, use
:doc:`verification`.
